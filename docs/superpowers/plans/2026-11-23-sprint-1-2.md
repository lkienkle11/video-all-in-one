# Video All-in-One, Sprints 1 and 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.1.0 (release pipeline, dev/prod split, self-written auto-update, bilingual UI shell, README) and v0.2.0 (media base, durable job queue, local cutting and export) of a Rust-native GPUI desktop app.

**Architecture:** One Cargo workspace: `apps/desktop` (GPUI views only), `crates/core` (domain, services, ports, no GPUI), `crates/media` (FFmpeg/FFprobe/yt-dlp, process runner, player adapter), `crates/storage` (SQLite), `crates/platform` (paths, binary resolver, updater), `xtask` (release tooling in Rust). UI observes and sends commands; the core decides job state; long work runs on Tokio.

**Tech Stack:** Rust (stable, edition 2021), GPUI + GPUI Kit (version pinned in Task 2), Tokio, rusqlite, serde, thiserror/anyhow, tracing, proptest, reqwest (rustls), ed25519-dalek, sha2, semver, FFmpeg/FFprobe/yt-dlp as external binaries.

**Spec:** `docs/superpowers/specs/2026-11-23-video-all-in-one-design.md`. Executors read it with this plan.

## Global Constraints

- Platforms: Windows 10+ (x64), macOS 13+ (Intel and Apple Silicon), Ubuntu 22.04+ (x64).
- Stack is final: Rust + GPUI + GPUI Kit. No WebView, no Tauri, no React, no C++ app code. A C or C++ library may be linked (for the player) only as a dependency.
- At least 85% of the code is Rust (line count over source files; docs, generated and vendored files excluded). Scripts are Rust (`cargo xtask`), not shell, Node or Python, except tiny platform files (workflow YAML, installer manifests).
- Never `unwrap()`/`expect()` outside tests. Library errors use `thiserror`, binaries `anyhow`. No shell strings: subprocess arguments are always argument lists.
- GPUI never runs FFmpeg or yt-dlp in an event handler. Output goes to a temp file and is renamed only after FFprobe verification. Never overwrite or delete a user's source video.
- Every modal and dialog: dimmed backdrop, background cannot scroll or be clicked, focus stays inside.
- UI is English and Vietnamese. No hard-coded UI text. README, GitHub About and code comments are English only. `CHANGELOG.md` has `### English` then `### Tiếng Việt` per version.
- Channel switch: Cargo feature `production`, set only by the release workflow. Dev build: name "Video All-in-One (Dev)", identifier `app.videoallinone.dev`, own data folder, no updater, never contacts the update endpoint. Production identifier `app.videoallinone`.
- `latest.json` has `"schema": 1`. The updater ignores a manifest with a schema it does not know. Updates are Ed25519-signed over the SHA-256 digest of the artifact; the public key is compiled in; the private key is only in GitHub Secrets (`UPDATE_SIGNING_KEY`) and the user's backup. No forced or minimum-version updates.
- Install fallback: if in-app install is impossible on an OS, download and verify the installer, then open it (or reveal it in the file manager).
- Database: copy the file to `<name>.bak-<schema>` before a migration; refuse to open a database whose schema is newer than the app knows.
- Job policy: downloads resume where yt-dlp and the source allow; cuts and encodes interrupted are marked `Failed` and retried from the start (temp files deleted on retry). Limits: 2 downloads, 1 encode at once, not configurable.
- Until sprint 4, FFmpeg, FFprobe and yt-dlp come from `PATH` (or a configured folder) with a clear message when missing.
- Git: branch `feat/init-video-all-in-one`. Commit title `type(scope): description` (Conventional Commits, commitlint). Commit body has the four sections in order: `**Scope:**`, `**What did:**`, `**Reviewed:**`, `**Tested:**`. Never add AI attribution or a co-author trailer. No push, merge or tag without the user's permission.
- Test-first for every task: watch the test fail for the right reason, then minimal code, then run the whole suite (`cargo test --workspace`).
- Verification commands for every task that changes code: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.

## Review Focus

Input classes and failures the spec implies but a happy-path test would miss, most likely first. Each has a test in the task named in brackets.

1. A source path with spaces, non-ASCII characters or a leading `-` (for example `-ss.mp4`). It must reach FFmpeg as a single argument and never be read as an option. [Task 14]
2. Segments that are reversed, zero-length, past the end of the video, overlapping or touching. They are sorted, clamped, merged, and empty ones dropped; an empty result is an error, not a silent no-op. [Task 11]
3. The output file already exists, or the output folder is read-only or the disk is full. The existing file is never overwritten silently, the job fails with a readable reason, and no partial file is left under the final name. [Task 15]
4. A truncated, corrupt or wrong-signature update download, or a manifest with an unknown `schema` or a lower version. Nothing is installed and the installed app keeps working. [Tasks 5, 6]
5. The app is killed while a job is `Running`. After restart the job is not stuck as `Running`: it becomes `Failed` (cut or encode) with its temp files cleaned, and the queue accepts new jobs. [Task 10]
